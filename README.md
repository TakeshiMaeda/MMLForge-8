MMLForge-8 v1.0.2<br>
mml.js v1.0.1

テキスト（MML）で書いて、その場で鳴らす。ブラウザだけで動くレトロ風BGM作成ツール＆再生エンジン。

MML（Music Macro Language）は `t120 l8 cdefgab` のように音楽をテキストで記述する伝統的な記法です。
MMLForge-8 は、その打ち込み・試聴・自動作曲・ゲームへの組み込みまでを、ビルド不要・依存ゼロの
バニラ JavaScript（Web Audio API）で提供します。音声ファイルは一切使いません。

## 使い方（エディタ）

`index.html` をブラウザで開くだけです。サーバもインストールも不要です。

- **ワークスペース** — 画面は DAW 風で、上部に再生・停止・ループ・音量のトランスポート、下部にヒントバーがあり、
  各機能はウインドウになっています。タイトルバーのドラッグで移動（画面の端やほかのウインドウに吸着）、右下の角で大きさ変更、
  `_` かタイトルバーのダブルクリックで最小化、`×` で閉じる（上部の「ウインドウ」から開き直せる）。`?` でそのウインドウの説明を開く。
  配置は保存されます。「整列」で開いているウインドウを大きさはそのままで重ならないように並べ直し、「初期化」で位置・大きさ・開閉を
  最初の状態に戻します。マウスを載せた部品の説明は下のヒントバーに出ます。画面が狭いときは縦に並びます
- **試聴プレイヤー** — 行頭から始まる行が1チャンネル（複数チャンネルは同時再生で和音・伴奏）。
  行頭に空白を入れた行は前のチャンネルの続きで、チャンネル内で自由に改行できる。ループ対応。内容は自動保存。
  コメントは `;`（そこから行末まで。行の途中でも可）と `/* ... */`（複数行またぎも可）。
  記法エラーは `チャンネル2 3行目 5文字目: 解釈できない文字です: "%"` のようにテキストエリア上の行と
  文字位置で示す
- **表示言語** — 日本語 / 英語。初回はブラウザの言語で決まり、右上のボタンで切り替えられます（選んだ言語は保存）
- **チャンネルON/OFF** — チャンネルごとのチェックボックスで再生するチャンネルを選択。
  再生中に切り替えると曲を止めずに即ミュート/復帰
- **記述を最適化** — 選択範囲（未選択なら全体）を読みやすい書き方に整える。`l8` の効いている場所の
  `c8` → `c`（付点は残す）、今と同じ値の `l` の言い直しを削除、絶対オクターブ指定 `o5` → `>`
  （同じオクターブなら削除。3オクターブ以上の跳躍は `>` を並べるより読みやすいので `o` のまま）。
  `l` 指定が無い区間に4分音符があればチャンネルの頭に `l4` を置いて数字を省く（`c4 d4 e4 f4` → `l4 c d e f`）。
  チャンネルで**最初に現れる `o` は残す**（暗黙の初期値 `o4` に寄りかからせない）ので、それより前の
  オクターブは触らない。リピート `[ ]` の中は周回ごとに状態が変わらないときだけ書き換え、仕上げに
  音符列が変わっていないか検算するので音は変わらない
- **mml.js用にコピー** — コメントを除去し、継続行を連結して1行=1チャンネルに整形した状態でコピー。
  他プロジェクトの `mml.js` へ持ち出すとき用（後述の「境界」を参照）
- **自動作曲（ガチャ）** — 雰囲気（しずか/幻想/疾走/緊迫/明るい）×小節数×シードで曲を生成して即再生。
  スケール（明暗）・キー・テンポ・激しさ・リズムch・ハーモニーは個別に上書き可能。
  同じシード+同じ設定なら同じ曲を再現できます。生成結果を手で編集して仕上げる使い方が本命です
- **メロディ伴奏付け** — 1行目のメロディからキーとコード進行を推定し、ベース・アルペジオ等の伴奏を自動生成
- **メロディ追い足し** — 1行目のメロディの続きを生成して末尾に追加。キー・進行・音域・激しさは
  メロディから推定し、直前の音から自然につなげる（何度でも追い足し可）。
  同主調スケール変更（暗転/明転）・オクターブ上下・盛り上げ（小節ごとに激しく）・締め（終止形）も指定できる
- **ミニ鍵盤** — クリック / PCキー（Z行・Q行）で演奏。音色・音量・エンベロープを設定可能
- **演奏録音 → MML変換** — 鍵盤で叩いたリズムとメロディを、BPM・最小音符で量子化してMML文字列に変換
- **音声 → MML変換（採譜）** — マイク録音または音声ファイル（WAV/MP3等）から鼻歌・口笛・単音楽器の
  メロディを検出してMMLに変換。録音中は検出音名をリアルタイム表示。単音（モノフォニック）のみ対応
- **リズムパッド** — drumbit風の打ち込み式リズム入力。4トラック×16分×最大4小節のグリッドをクリックで
  打ち込み（各トラックに楽器プリセット: キック/スネア/ハット等を割り当て、o/v/@e を微調整可）。
  ループ再生で確認してMML出力・本編へ挿入。打点が重ならないトラックは1チャンネルにまとめて出力され、
  同一ステップの同時打鍵があるときだけチャンネルが分かれる

※ ブラウザの自動再生制限により、最初のクリック等の操作後に音が出ます。

## MML記法

| 記法 | 意味 |
|---|---|
| `c d e f g a b` | 音符。直後に `#` / `+` でシャープ、`-` でフラット（例: `c#` `b-`） |
| 数字・付点 | 音長。`c4`=四分 `c8`=八分 `c12`=三連 `c4.`=付点四分（省略時は `l` の値） |
| `r` | 休符（音長指定は音符と同じ） |
| `o4` / `>` / `<` | オクターブ指定 / +1 / -1（`o4` の `a` = 440Hz） |
| `l8` | デフォルト音長（初期値4） |
| `t140` | テンポBPM（初期値120。全チャンネルに書くこと） |
| `v0`〜`v15` | 音量（初期値10） |
| `q1`〜`q8` | ゲートタイム。8=音長いっぱい、小さいほどスタッカート（初期値8） |
| `@0`〜`@4` | 音色: 0=sine 1=square 2=triangle 3=saw 4=noise（初期値1） |
| `@e3,0,100,40` | エンベロープ: attack(ms), decay(ms), sustain(%), release(ms)。初期値 `@e3,0,100,40` |
| `&` | タイ/スラー。前の音符と繋いでアタックを鳴らし直さない。`c4&c8`=タイ（長くする） `c4&e4`=スラー（音程だけ差し替え） |
| `m120,5,30` | LFO（ビブラート）: 遅れ(ms), 速さ(Hz), 深さ(セント。中心から±)。初期値 `m0,0,0`＝無効 |
| `p60` | ポルタメント。`&` の繋ぎ目を60msかけて滑らせる（`&` が無い並びには効かない）。初期値 `p0`＝瞬時 |
| `@b-200,60` | ベンド。出だしを200セント下（負で下・正で上。`@b+200,60` とも書ける）から60msで正規の音程へ。**次の音符1つにだけ効く** |
| `[ ... ]3` | リピート3回（ネスト可）。1チャンネルの音符+休符が100万を超えるとエラー |
| `[ ... ]` / `[ ... ]0` | 数字なし・0 は無限ループ: 2周目以降ここから繰り返す（イントロ付きループ用。チャンネル末尾にのみ書ける） |
| `\|` | 小節区切り（再生には影響しない。見た目整理用） |

- `o` `v` `q` `@` の値が表の範囲を外れるとエラーです（黙って丸めません）。`>` `<` で `o0`〜`o8` を出るのも同様
- `@e` の sustain は % なので 0〜100。それ以外はエラー

- noise（`@4`）は音程でバンドパスフィルタが動くため、`o3`=キック、`o5`=スネア、`o7`=ハットのような
  打楽器の打ち分けができます
- noise は低いほど音量が下がります。バンドパスで捨てる帯域ぶんをゲインで補償していますが、補償には
  上限があり、**約375Hz（`o4` の `f` 付近）から下は補償しきれません**（`o3` のキックで約4.6dB、
  `o2` なら約7.6dB小さい）。低い打楽器が細いと感じたら `v` を上げてください
- `&` で繋いだ音は**1回しか発音しません**（アタック・音量・エンベロープは繋いだ先頭の音のものを全体に使う）。
  `m` の遅れも繋いだ全体の頭から数えるので、長く伸ばすほどビブラートが育ちます
- `m` の深さがセント（半音=100）なのは、音程の知覚が対数だからです。Hz指定だと低音では揺れが浅く、
  高音では深く聞こえてしまいますが、セントなら全オクターブで同じ揺れ幅に聞こえます。
  速さは Hz でテンポ非連動です（ビブラートは拍ではなく奏者の動きなので）
- `@b` と `m` はどちらもセント単位で、同じ detune の上で加算されます。
  `@b-100,60 m120,5,30` なら「しゃくり上げてから揺れ始める」になります
- 半音・全音のように音名で書ける幅の上下（ハーモニカのベンドから戻る奏法など）は `p` と `&` で書けます:
  `p40 o4 e16&d16&e2.` — アタックは1回だけで、E→D→E とひと息で動きます
- 無限ループの例: `t120 イントロ [本体]0` — イントロは1回だけ鳴り、以降は本体を繰り返します
  （ループ再生OFFのときは本体1回で停止）。複数チャンネルに書いた場合は最も遅い開始点が曲のループ開始点になり、
  短い無限ループ（ドラムパターン等）は曲の長さまで自動で敷き詰められます
- `&` の直後にループ開始点を置けます: `c4& [d4 e4]0` は1周目 c→d と繋がって鳴り、2周目以降は d4 を頭から鳴らします

## エンジンを自分のゲーム/アプリに組み込む

`mml.js` 1ファイルをコピーして読み込むだけです（依存なし・約560行）。グローバル `MMLPlayer` が持つメンバーは以下の9つです（アルゴリズムの詳細は `mml.js` 本体のコメントを参照してください。ソースは公開されています）。

| メンバー | 型 | 説明 |
|---|---|---|
| `play(channels, opts?)` | `(string \| string[], { loop?: boolean }) => { duration, loopStart }` | 再生を始める。`channels` は1チャンネル分のMML文字列、またはその配列（各要素が1チャンネルとして同時に鳴る）。`opts.loop`（既定 `true`）でループ再生のON/OFF。戻り値の `duration` は1周目の秒数、`loopStart` は無限ループ `[ ]0` の開始秒（未使用時 `null`）。パース失敗時は `MMLError` を投げ、その間は再生中の曲を止めない |
| `stop()` | `() => void` | 再生を止める。クリックノイズを避けるため短くフェードしてから切る |
| `setVolume(v)` | `(number) => void` | マスター音量を設定（0〜1にクランプ） |
| `setTrackMute(i, muted)` | `(number, boolean) => void` | `play()` に渡した配列の `i` 番目（0始まり）を再生中に即ミュート/復帰する |
| `parse(src, track?)` | `(string, number?) => { notes, duration, tempo, loopStart }` | 1チャンネル分のMMLを解析するだけで再生はしない（作曲支援ツール用）。`track` はエラーに付ける番号（既定0）。`notes` は `{time,dur,midi}` の配列 |
| `playing` | `boolean`（読み取り専用） | 再生中かどうか |
| `volume` | `number`（読み取り専用） | 現在のマスター音量（0〜1） |
| `MMLError` | クラス | 記法エラーの型。`instanceof` で判別できる。`code` / `params` / `track` / `pos` / `message` を持つ（詳細は次の「エラー」節） |
| `version` | `string` | エンジンの版（例: `'1.0.0'`。`v` は付かない） |

呼び出し方の例:

```html
<script src="mml.js"></script>
<script>
  // 再生（配列の各要素が1チャンネル。同時に鳴る）
  MMLPlayer.play([
    't120 l8 o5 @1 v11 cc gg aa g4',
    't120 l4 o3 @2 v9  c  e  g  e',
  ], { loop: true });

  MMLPlayer.stop();           // 停止
  MMLPlayer.setVolume(0.5);   // マスター音量 0〜1
  MMLPlayer.setTrackMute(0, true);  // チャンネル0を即時ミュート（false で復帰。再生中に有効）
  MMLPlayer.playing;          // 再生中か
  MMLPlayer.parse('t90 cde'); // 解析のみ → { notes:[{time,dur,midi}], duration, tempo, loopStart }
                              // 第2引数にチャンネル番号(0始まり)を渡すとエラーの track に入る
  MMLPlayer.MMLError;         // エラーの型（instanceof で判別できる）
</script>
```

```js
// 記法エラーの受け取り方（mml.js は文言を持たないので、表示は自分のアプリの言葉で作る）
try {
  MMLPlayer.play(channels);
} catch (e) {
  if (e instanceof MMLPlayer.MMLError) {
    console.log(e.code);    // 'BAD_CHAR' … エラーの種類
    console.log(e.params);  // { char: '%' } … 文言に埋める値
    console.log(e.track);   // 0 … 何本目のチャンネルか（曲全体のエラーは null）
    console.log(e.pos);     // 4 … 渡した文字列の中の位置（1始まり）
  }
}
```

`code` の一覧（この25個が外向きの約束です。`params` の欄が空のものは埋める値なし）:

| 分類 | code | params |
|---|---|---|
| 文字・音長 | `BAD_CHAR` / `LEN_MIN` | `char` / — |
| 引数の区切り | `COMMA_REQUIRED` | `label`（`m` `@e` `@b`） |
| リピート上限 | `TOO_MANY_STEPS` | `max` |
| タイ `&` | `TIE_NO_PREV` / `TIE_NO_NEXT` / `TIE_REST` | — |
| 括弧・ループ | `UNMATCHED_OPEN` / `UNMATCHED_CLOSE` / `LOOP_NOT_LAST` / `LOOP_EMPTY` | — |
| 単独コマンド | `O_RANGE` / `OCT_OVER` / `OCT_UNDER` / `L_ARG` / `T_ARG` / `V_RANGE` / `Q_RANGE` / `P_ARG` | — |
| 複数値コマンド | `M_ARGS` / `E_ARGS` / `E_SUSTAIN` / `B_ARGS` | — |
| 音色 | `WAVE_RANGE` | `max` |
| 再生 | `NO_NOTES` | — |

- 再生は lookahead 方式のスケジューラで、テンポが揺れません
- `play()` はパース失敗時に `MMLError` を投げます（再生中の曲は守られます）。**表示用の文言は持ちません**。
  どの言語のアプリからでも使えるよう、種類を表す `code` と、文言に埋める値 `params` だけを渡します
  （`message` は `code` と同じ文字列）。`pos` は渡した文字列の中の位置で、リピート `[ ]n` の後ろでも
  展開後ではなく書いたままの位置を指します
- 文言はアプリ側で `code` から作ります。このリポジトリでは `js/mml-messages.js` が日本語と英語の表を持ち、
  `js/core.js` の `locateError` が行と桁を付けて `チャンネル2 3行目 5文字目: 解釈できない文字です: "%"` にしています
- 音符も休符も無いものを `play()` すると `code` が `NO_NOTES` の `MMLError` になります（`track` `pos` は `null`）
- ループ再生OFFのときは、曲の尺と最後の音のリリースが終わってから自動で止まります。`stop()` は
  短くフェードしてから音を切ります（クリックノイズ対策）

### エディタの機能と mml.js の機能の境界

**コメント（`;` `/* */`）とチャンネル分割（行頭/継続行）は `index.html` の機能で、`mml.js` にはありません。**
エディタは MMLPlayer に渡す前にコメントを空白へ潰し、テキストエリア1枚をチャンネル文字列の配列へ分解しています。

`mml.js` が読み飛ばすのは **半角スペース・タブ・改行・`|`** の4つだけで、それ以外の未知の文字は
`code` が `BAD_CHAR`（`params.char` がその文字。例: `;`）の `MMLError` になります。逆に言えば空白と改行は自由なので、
テンプレートリテラルで整形して渡せます:

```js
MMLPlayer.play([`
  t120 l8 o5 @1 v11
  cc gg | aa g4
`]);
```

| 記法・機能 | mml.js 単体 | index.html |
|---|---|---|
| 音符・音長・`o` `l` `t` `v` `q` `@` `@e` `&` `m` `p` `@b` `[ ]` | ○ | ○ |
| 空白・タブ・改行・`\|`（無視される） | ○ | ○ |
| コメント `;` `/* ... */` | **×** | ○ |
| 行頭=新チャンネル / 行頭空白=継続行 | **×**（配列で渡す） | ○ |

エディタで書いた曲を持ち出すときは、エディタのウインドウにある **「mml.js用にコピー」** を使ってください。
コメントを除去し、継続行を連結して1行=1チャンネルに整形したものがコピーされるので、各行をそのまま
`MMLPlayer.play()` の配列要素にできます。エディタの記法ごと使いたい場合は、`js/core.js` 内の
`stripComments()` / `parseChannelBlocks()`（依存ゼロの純関数）も一緒にコピーしてください。

なお `@e3,0,100,40` の数値とカンマの前後だけは**半角スペースしか読み飛ばしません**（改行やタブを挟むとエラー）。

## テスト

アプリ本体はビルド不要ですが、テストだけ用意してあります。Node があれば追加の準備は要りません（npm も設定ファイルも不要）。

```
node test/run.js            # 全部
node test/run.js parser     # 名前で絞り込み
```

見ているのは**数えられるもの**だけです。

- MML記法の正常系（音長・オクターブ・リピート・`&` `m` `p` `@b`）
- **エラーのコードと位置**。`mml.js` が投げる `code` と `pos` は外向きの約束なので固定しています。位置は必ず原文の文字位置（リピートの後ろでもずれない）
- **エラーコードと文言表の同期**。`mml.js` のソースからコードを拾い、`js/mml-messages.js` に文言があるかを突き合わせます（片方だけ増やすと落ちます）
- エディタ側のテキスト処理（コメント除去・チャンネル分割・小節チェックとその報告文）
- ワークスペースのウインドウ位置の計算（初期配置・画面内に収める・吸着・整列・保存データの読み込み）
- **表示言語**。英語表示で日本語が見えないこと（HTML も JS も）、日本語と英語の対が揃っていること、言語を変えても生成される曲が変わらないこと
- **README の日英の同期**。記法表とエラーコード表が日英で一致し、エラーコードが `mml.js` と一致すること
- `songs/*.mml` の尺・小節数・チャンネル同尺

音量バランスや音色や演奏表現は**耳で確かめるしかない**ので、テストの範囲外です。

## 小節チェック

手書きで一番多い事故は「1小節に入れる音符の数を間違える」ことです。MMLとしては何も間違っていないのでパーサは黙って通し、再生してチャンネルがズレて初めて気づきます。

再生行の「小節チェック」は、各チャンネルの尺が小節の整数倍か・全チャンネルで揃っているかを調べ、崩れていれば**小節線から外れ始めた行と小節位置**を示します。1小節が4分音符いくつぶんかは自分で指定してください（4/4なら4、6/8は8分6つ＝4分3つなので3）。

無限ループ `[ ]0` のチャンネルは、再生時に本体が曲末まで敷き詰められます。小節チェックも**敷き詰めた後に鳴る長さ**で数えるので、`gggggggg` と `[c]` は同じ2小節として同尺OKになります（`前奏N小節 + 本体M小節 × K回` の内訳も表示）。無限ループは曲末で打ち切られるので**長さは必ず曲と揃い**、同尺NGにはなりません（有限リピート `[ ]2` は打ち切られないので、はみ出せば同尺NGになります）。本体の長さがループ区間長を割り切れないときは、繋ぎ目で本体の途中から頭に戻るため `曲末で途中まで` と内訳に添えますが、書き手の意図次第なので要確認にはしません。

曲の途中でテンポが変わるチャンネルは小節長を1つに決められないので、**判定不能として報告します**（誤った小節数を出さないため）。

## 動作環境

モダンブラウザ（Chrome / Edge / Firefox / Safari）。Web Audio API を使用します。テストの実行には Node が要ります。

## 出自

ブラウザゲームのBGMを「音声ファイルなし・コード合成のみ」で作るために生まれたツールです。

## クレジット

外部ライブラリへの依存はありません。以下は本体に取り込んで利用している既存の成果です。

- **mulberry32**（擬似乱数, `js/mml-composer.js`） — Tommy Ettinger 作の小型PRNG。パブリックドメイン（CC0）扱いのスニペットで、決定的な曲生成（同じシード+設定なら同じ曲）に使用しています。
- **YIN法**（ピッチ解析, `js/mml-audio.js`） — de Cheveigné, A. & Kawahara, H. (2002) "YIN, a fundamental frequency estimator for speech and music" で発表された基本周波数推定アルゴリズムを、本プロジェクトで独自に実装したものです（音声→MML採譜に使用）。
